# Логика прогресса маршрутов (US-06)

Клиент хочет **последовательную разблокировку по сложности**: пока не проехал предыдущий — следующий для брони из ЛК закрыт.

## Цепочка (по бизнес-плану)

```
Зелёное озеро  →  Памятник  →  Родник  →  Экспедиция
   (1) открыт        (2)            (3)         (4)
   сразу          после 1       после 2      после 3
```

| order | Маршрут | Сложность | Цена | Когда открыт для брони в ЛК |
|-------|---------|-----------|------|------------------------------|
| 1 | Зелёное озеро | лёгкий | 5 500 ₽ | всегда у нового аккаунта |
| 2 | Памятник | средний | 7 500 ₽ | админ отметил «пройден» по №1 |
| 3 | Родник | средний+ | 10 000 ₽ | отмечен «пройден» по №2 |
| 4 | Экспедиция | сложный | 12 000 ₽ | отмечен «пройден» по №3 |

**Ночной квест** — отдельный продукт (не звено этой цепочки по умолчанию). Если Заказчик захочет встроить в прогресс — отдельное правило в CMS.

---

## Кто что видит

### Гость без регистрации
- Видит **все** карточки маршрутов на сайте (маркетинг, цены, описания).
- Может оставить **обычную заявку** без прогресса (ТЗ).
- Не видит статусы «открыт / закрыт» как в ЛК.

### Клиент в ЛК (зарегистрирован)
- В списке маршрутов: №1 — **доступен**, остальные — **замок** + подпись «откроется после прохождения …».
- Кнопка «Забронировать» только у **открытых**.
- После заезда **админ в Payload** ставит галочку «маршрут пройден» → открывается следующий номер.
- Пройденные остаются доступны для повторной брони (не закрываем назад).

---

## Сценарий приёмки (как в ТЗ)

1. Новый аккаунт → бронь только **Зелёное озеро**.
2. Админ → «пройден» по маршруту 1.
3. В ЛК открывается **Памятник**.
4. Аналогично 2→3→4.

Пароли хэшируются, доступ к ЛК только авторизованным.

---

## Данные в CMS

**`routes`:** поле `progressOrder` (1…N), `requiresPrevious: true`.  
**`route-progress`:** `user` + `route` + `completedAt` + `confirmedByAdmin`.  

Правило доступа:

```
маршрут N открыт  ⇔  N === 1  ИЛИ  существует progress по маршруту (N-1)
```

Админ не «открывает руками следующий», а **подтверждает прохождение текущего** — следующий считается сам.

---

## UI (минимум, без отдельного макета)

- Карточка: бейдж «Доступен» / «Закрыт» / «Пройден».
- Закрытая: disabled CTA, иконка замка.
- Опционально на публичной странице маршрутов для залогиненных — те же бейджи (если успеем в US-06; иначе только в `/lk`).
